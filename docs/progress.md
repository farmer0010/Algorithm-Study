- 재귀(Recursion) 기반 "믿음의 도약" (from/to/via 역할 교대) — 신규 도입 완료, 왕복 0회 (하노이의 탑)
- 트리 구성(좌표 기반 BST 삽입) + 전위/후위 순회 재귀 — 신규 도입 완료 (길 찾기 게임)
- 1차원 순수 재귀 (분할 후 위임 패턴, `cut(M,N)=N+cut(M-1,N)`) — 신규 도입 완료, 왕복 3회 (종이 자르기)
- 부모 체인 단방향 재귀 (트리형이지만 한 방향으로만 타고 올라가는 단순 구조) — 신규 도입 완료, 왕복 1회 (다단계 칫솔 판매)
- 백트래킹 + 1차원 압축 설계 (2차원 보드 대신 depth당 값 하나만 기록) — 재응용 완료, 왕복 2회 (N-Queen)
- 연속 구간(Run-length) 그룹핑 + 대표 원소 키 설계 (TreeMap 활용 정렬) — 신규 도입 완료, 왕복 1회 (외톨이 알파벳)
- 백트래킹(DFS) 기반 순열 배정 (1:1 매칭 최적화) — N-Queen 패턴 재응용, 왕복 거의 0회 (체육대회)
- 역방향 재귀 (자식→부모 인덱스 역산, 몫/나머지 활용) — 다단계 칫솔 판매 패턴 재응용 + 신규 수식, 왕복 2회 (유전법칙)

- 좌표평면 방향탐색 (dx/dy 순환 배열, 격자 BFS 패턴 재적용 시 부호 재검증 필요) — 재응용 완료, 왕복 4회 (실습용 로봇)

## Lv.4 진입 판단 (Day 134 기준 갱신)
- **긍정적 신호 강화:** 체육대회(백트래킹, N-Queen 재응용)를 코치 개입 최소한으로 첫 코드에서 바로 통과 — 재귀/백트래킹 감각이 "재귀"라는 표찰이 없는 완전탐색형 문제에도 자연 전이됨을 확인. 재귀 관련 재검토 기준(2번: 왕복 3~4회 이내)은 사실상 충족.
- **신규 긍정 신호 (Day134):** 보물 지도(좌표 기반 BFS)에서 배열 크기를 `n+1`로 지적 없이 스스로 설계함 — 그래프형 배열 크기 재검토 기준(1번)에 대한 첫 데이터 포인트 확보. 다만 1건뿐이라 "2~3세션 연속" 기준 충족까지는 추가 관찰 필요.
- **미해결/신규 신호:** "선언은 했지만 반환 흐름에 연결 안 됨" 패턴이 재귀 호출 결과 미반환, 분기 일부 경로 return 누락 등으로 재발하여, 이 패턴군 자체의 완전한 해소는 아직 진행형. Day134(보물 지도)에서는 이 패턴 대신 "상태(신발 여부)를 확장했을 때 관련된 모든 참조 지점(큐 삽입값, visit 마킹 인덱스, 범위 체크)에 일관되게 반영하지 못하는" 새로운 유형의 실수가 다수 관찰됨 — 왕복 횟수 자체가 6회 이상으로 늘어난 주된 원인.
- **신규 데이터 (Day135, 부분적):** 트리+백트래킹이라는 완전 신규 패턴에서 왕복 8회 이상 소요됨 — 재검토 기준 2번(왕복 3~4회 이내)은 신규 패턴 도입 세션 특성상 아직 미충족. 다만 막힐 때마다 원인을 스스로 좁혀나가는 디버깅 태도 자체는 안정적으로 유지됨. 그래프형 배열 크기(n+1) 관련 데이터는 이번 문제엔 해당 사항 없음(인접 리스트 방식이라 별도 관찰 불가) — 다음 그래프형 문제에서 계속 관찰.
- **결론:** 재귀/백트래킹의 "설계 전이력"은 뚜렷하게 좋아졌고, 그래프형 배열 크기 감각도 첫 데이터가 긍정적. 다만 "상태 공간을 확장할 때 전체 참조 지점의 일관성을 유지하는 것"이 새로운 관찰 대상으로 떠올랐음 — 다음 그래프/상태공간형 문제에서 계속 추적할 것.

## 최근 취약 포인트 (누적 추적용)
- **"시각(timestamp)"과 "기간(duration)" 혼동 (Day134 신규):** 카페 확장에서 도착 시각(절대적 시점)과 제조 시간(상대적 기간)을 `Math.max`로 섞어 비교하려는 실수가 반복됨. 변수 이름을 `startTime`/`endTime`처럼 명확히 분리한 뒤에야 교정됨.
- **상태 공간 확장 시 참조 지점 전체의 일관성 누락 (Day134 신규):** 보물 지도에서 2차원 visit을 3차원(좌표+신발상태)으로 넓히는 아이디어 자체는 빠르게 캐치했으나, 초기화·범위체크·방문마킹 등 관련된 모든 참조 지점에 빠짐없이 반영하는 데 여러 차례 왕복이 필요했음. 특히 "큐에 넣는 상태값과 visit에 마킹하는 인덱스는 항상 동일해야 한다"는 원칙을 마지막에야 체득함 — 상태 하나를 추가/변경할 때 관련 참조 지점을 체크리스트처럼 훑는 습관이 필요.
- **조건식 설계 시 AND/OR 혼동 및 상수 오용 (Day133):** 운영체제에서 `while(!pq.isEmpty() && idx<10)`처럼 논리연산자 방향 착오, 배열 길이 대신 무관한 상수(10, 점수 범위와 혼동) 사용. 반례와 손 시뮬레이션으로 매번 스스로 교정함 — 개선 여지는 있으나 자가 교정 속도는 빠른 편.
- **배열 인덱싱이 이미 부호를 담고 있음에도 위에 중복 분기(if)를 씌우는 습관 (Day133):** 실습용 로봇에서 `dx[d]`,`dy[d]` 값 자체로 충분한데 `if(d==0||d==2)` 식 분기를 추가로 씀. 다음엔 배열 인덱싱만으로 분기 없이 처리하는 걸 스스로 시도해볼 것.
- **격자탐색 부호를 다른 도메인(좌표평면)에 무비판적으로 재사용 (Day133):** 예시 손 검증으로 즉시 자가 교정함 — 개선 신호로 볼 수 있음.
- **"선언은 했지만 반환 흐름에 연결 안 됨" 패턴의 새로운 변형 (Day132):** 재귀 호출 자체를 호출만 하고 결과를 받지도 리턴하지도 않는 형태로 재발함(유전법칙). Day131의 즉각적인 자가 교정과 달리, 이번엔 코치 지적이 필요했음 — 재귀 호출 결과를 반드시 변수에 담거나 즉시 리턴해야 한다는 원칙을 재귀 문제 도입부에서 매번 짚어줄 필요.
- **분기가 있는 함수에서 "모든 실행 경로가 값을 리턴하는가" 확인 누락 (Day132):** 유전법칙에서 `if`문만 작성하고 `else`를 빠뜨림. 조건 분기가 여러 개인 함수를 짤 때, 코드 작성 전 케이스를 말로 먼저 나열하는 습관 필요.
- **"선언은 했지만 반환 흐름에 연결 안 됨" 패턴 (Day131, 개선 신호):** 종이 자르기에서 재발했으나, 코치 지적 없이도 다음 시도에서 거의 바로 스스로 교정 — 자가 교정 속도가 빨라짐 (단, Day132에 재귀 호출 형태로 새로운 변형이 재발했으므로 완전 해소는 아님).
- **char 리터럴과 String 리터럴 혼동 (Day131):** `'-'`(char)와 `"-"`(String)를 `.equals()`로 비교하며 항상 false가 나와 NPE 발생. `.equals()`는 String 객체끼리만 의미가 있다는 걸 실제 런타임 에러로 체득. Day132(유전법칙)에서는 이 교훈을 스스로 적용해 `.equals()`를 정확히 사용함 — 개선 확인.
- **배열 인덱스와 저장값의 역할 혼동 (Day131):** N-Queen에서 `g_col[row] = col`과 `g_col[col] = row`를 헷갈림 — "이 배열을 나중에 조회할 때 어떤 규칙으로 읽을 것인가"를 먼저 정하고 그 규칙에 맞춰 저장해야 함을 스스로 교정.
- **빈 컬렉션에서 peek()/pop() 호출 순서 실수 (Day129):** `!stack.isEmpty() && 조건` 순서(short-circuit)로 방어해야 함을 지적 후 즉시 이해·적용. 스택/큐 계열 문제에서 계속 관찰 필요.
- **백트래킹 시 방문 배열(visit) 초기화 위치 오류 (Day129):** 재귀 함수 내부에서 매번 재생성하면 상태가 소실됨을 지적 후 정확히 이해. Day132(체육대회)에서는 `isVisit[]`을 함수 밖에서 한 번만 생성해 정확히 재사용 — 개선 확인.
- **원본 문자열 vs split 결과 배열 인덱싱 혼동 (Day 128):** 새 변수를 만든 시점에 "이제부터는 이 변수만 써야 한다"를 의식적으로 표시하는 습관 필요.
- **Map 조회 API 선택 혼동 (Day 128):** `get`/`getOrDefault`/`computeIfAbsent` 차이. "이 Key가 항상 존재를 보장받는가?"를 먼저 판단하고 API를 고르는 습관 필요.
- **그래프형 배열 크기 설계 실수 (관찰 지속, Day134 긍정 데이터 1건):** Day133까지 그래프형 문제가 없어 데이터 없었으나, Day134 보물 지도(좌표+BFS)에서 `n+1` 크기를 지적 없이 스스로 적용함. 다음 그래프/트리형 문제(양과 늑대)에서 재확인 예정.
- **구조(자료구조) 확장 시 참조 지점 전체 갱신 누락 (Day135 재발):** 보물 지도(Day134)에서 visit 배열 관련으로 나타났던 패턴이, 양과 늑대에서는 **candidate 리스트** 관련으로 재발함 — "자식들을 candidate에 추가"는 바로 떠올렸지만, 백트래킹 원복 시 "자식들을 candidate에서 다시 제거"하는 것은 별도 지적 후에야 반영함. 상태를 담는 자료구조(visit이든 candidate든)를 확장/변경할 때마다 "원복 시 무엇을 되돌려야 하는지"를 짝지어 생각하는 습관이 아직 완전히 자동화되지 않음 — 계속 추적 필요.
- **초기화 단계의 경계 조건(이중 처리) 실수 (Day135 신규):** 루트 노드를 "이미 방문 완료" 상태로 세팅하면서, 동시에 candidate 목록에도 루트 자신을 넣어버려 재귀 진입 시 루트가 다시 한번 카운트되는 실수 발생. "이 노드는 이미 처리 완료다"라고 표시하는 로직(visit, 카운트)과 "다음 대상 후보로 넣는다"는 로직을 같은 노드에 동시에 적용하지 않도록, 초기화 코드를 짤 때도 "지금 이 값은 이미 완료된 상태인가, 아직 대기 중인 상태인가"를 구분하는 습관 필요.
