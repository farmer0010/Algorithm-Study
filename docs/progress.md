- Day 133: PCCP 모의고사 1회를 운영체제(Lv.3)로 완주하고, 곧바로 2회 챕터(실습용 로봇 Lv.1, 신입사원 교육 Lv.2)를 신규 개척. **3문제 모두 완주, 왕복 8회 내외/4회/0회.** 이벤트 기반 시뮬레이션(대기열/실행대기열 PQ 이중 관리)을 신규 도입 — 우선순위 정렬 기준(점수 우선, 호출시각은 타이브레이크)을 반례로 스스로 검증했고, 조건식(AND/OR 혼동, 배열 길이 대신 무관한 상수 사용) 실수는 있었으나 매번 반례·손 시뮬레이션으로 자가 교정. 좌표평면 방향탐색(실습용 로봇)에서 격자 BFS의 row/col 부호를 그대로 가져다 쓰다 어긋난 것을 예시 검증으로 교정. 그리디+최소힙 반복 병합(허프만 스타일, 신입사원 교육)은 왕복 0회로 최고 성과.
- Day 134: PCCP 모의고사 2회 챕터 완주(카페 확장 Lv.2, 보물 지도 Lv.3) — 세 번째로 준비했던 양과 늑대(Lv.3)는 미완주, Day 135로 이월. **2문제 완주, 왕복 7~8회/6회 이상.** 카페 확장에서는 "시각(timestamp)"과 "기간(duration)" 혼동으로 여러 차례 헤맸으나 결국 Day92 호텔 대실 구간 겹침 패턴(투 포인터)을 스스로 재소환해 O(n)으로 해결. 보물 지도에서는 좌표+아이템(신발) 사용 여부를 함께 추적하는 3차원 상태 공간 BFS를 신규 도입 — 좌표 배열 크기(n+1)는 지적 없이 스스로 적용했으나, "큐에 넣는 상태값 = visit 마킹 인덱스"를 일치시켜야 한다는 원칙에서 여러 차례 왕복함.
- Day 135: 양과 늑대(Lv.3, 카카오 2022) 신규 도입 — 트리(이진 트리) + 백트래킹, 세트 중 1문제만 완주(왕복 8회 이상, 신규 패턴 감안 시 합리적 수준). **"정적 구조(인접 리스트)"와 "동적 상태(현재 방문 가능한 후보 목록)"를 분리 관리**해야 한다는 개념을 다수의 소크라테스식 질문 끝에 스스로 체화함. candidate 목록을 향상된 for문으로 순회하다 `ConcurrentModificationException` 위험을 인지하고 스냅샷(snapshot) 방식으로 스스로 회피. 백트래킹 "복원 4종 세트"(카운트/visit/자식후보 제거/자기자신 복원)를 여러 차례 왕복 끝에 대칭적으로 완성. 초기화 단계에서 루트 노드를 candidate에도 넣고 카운트에도 반영해 이중 카운팅되는 경계 조건 실수가 있었으나, 원인 설명 직후 정확히 이해하고 수정함.
- Day 136: 가사 검색(Lv.4, 카카오 2020) 신규 도입 — Trie(트라이) 자료구조를 처음부터 설계(정방향+역방향 이중 트라이, 접두사/접미사 와일드카드 분기)해 **정확성 100% 한 번에 통과.** 효율성 테스트에서 메모리 초과가 나자, 노드당 `int[10001]` 배열 방식의 실제 메모리 낭비량(약 80GB)을 스스로 계산해 원인을 정확히 진단하고, `Map<Integer,Integer>` 기반 공간 최적화로 전환해 해결함. 이어서 효율성 테스트 중 하나(엣지케이스: `?`가 맨 앞부터 시작해 확정 글자가 0개인 쿼리)에서 실패했을 때도, "`?`가 맨 처음 나오면 for문이 안 도니까 루트 자체가 카운팅이 안 된다"는 원인을 스스로 정확히 진단함. **1문제 완주(왕복 15회 이상, 신규 자료구조 + 공간복잡도 최적화라는 두 가지 새 개념을 한 세션에 동시 도입한 것을 감안하면 합리적 수준).** 세트로 준비했던 징검다리(Lv.4)는 사용자 판단으로 다음 세션 이월. 세션 종료 시 사용자가 "Lv.2~3을 더 다지고 싶다"는 의견을 표명함 — 코치 관찰로는 실제 성과 대비 다소 과도한 자기 저평가 신호로 보임.

## 최근 다룬 핵심 유형 (중복 방지 체크리스트)
- BFS (미로/리코쳇 로봇 등, 단어 변환 — 암묵적 그래프 재응용)
- 그리디 - 투 포인터
- 해시맵 카운팅 (정렬 + Map 조합)
- 최소 힙(PriorityQueue) 기반 구간 스케줄링 (호텔 대실)
- 큐 두 개 시뮬레이션 (순환 배열) (두 큐 합 같게 만들기)
- 구간 합 / 차분 배열 (Difference Array) (파괴되지 않은 건물)
- 이분 탐색 (파라메트릭 서치) — 신규 도입 완료 (입국심사)
- 수학적 완전탐색 (약수 관계) — 신규 도입 완료 (카펫)
- 그래프 최단경로 (플로이드-워셜) — 신규 도입 완료 (합승 택시 요금)
- DP (동적 계획법) — 신규 도입 완료 (정수 삼각형, Top-down 누적 방식)
- Union-Find(분리집합) + MST(크루스칼) — 신규 도입 완료 (섬 연결하기)
- 그래프 단일 출발점 최단경로 (다익스트라, PriorityQueue + Lazy Deletion) — 신규 도입 완료 (배달)
- DP 2차원 격자형 (min(위, 왼쪽, 대각선) + 1 패턴) — 신규 도입 완료 (가장 큰 정사각형 찾기)
- 플로이드-워셜의 "관계 추론(도달 가능성)" 응용 — 신규 도입 완료 (순위)
- 다단계 문자열 규칙 순차 처리 (7단계형) — 재응용 완료, 왕복 0회 (신규 아이디 추천)
- 재귀(DFS) 기반 "포함/제외" 조합 생성 — 메뉴 리뉴얼 패턴 재응용 완료 (순위 검색)
- 해시맵 전처리 인덱싱 (등록 시점에 미리 다수 키로 펼쳐두기) — 신규 도입 완료 (순위 검색)
- 이진 탐색 lower-bound 응용 ("특정 값 이상 개수 세기") — 입국심사 패턴 재응용 완료 (순위 검색)
- BFS depth 관리 (Node+depth 묶음 방식) — 재응용 완료, 왕복 1회 (단어 변환)
- 모노토닉 스택 (Monotonic Stack) — 신규 도입 완료, 왕복 4~5회 (주식 가격)
- 백트래킹(DFS) 기반 조합 배정 + Set을 이용한 순서무관 중복 제거 — 신규 도입 완료, 왕복 1회 (불량 사용자)
- 재귀(Recursion) 기반 "믿음의 도약" (from/to/via 역할 교대) — 신규 도입 완료, 왕복 0회 (하노이의 탑)
- 트리 구성(좌표 기반 BST 삽입) + 전위/후위 순회 재귀 — 신규 도입 완료 (길 찾기 게임)
- 1차원 순수 재귀 (분할 후 위임 패턴, `cut(M,N)=N+cut(M-1,N)`) — 신규 도입 완료, 왕복 3회 (종이 자르기)
- 부모 체인 단방향 재귀 (트리형이지만 한 방향으로만 타고 올라가는 단순 구조) — 신규 도입 완료, 왕복 1회 (다단계 칫솔 판매)
- 백트래킹 + 1차원 압축 설계 (2차원 보드 대신 depth당 값 하나만 기록) — 재응용 완료, 왕복 2회 (N-Queen)
- 연속 구간(Run-length) 그룹핑 + 대표 원소 키 설계 (TreeMap 활용 정렬) — 신규 도입 완료, 왕복 1회 (외톨이 알파벳)
- 백트래킹(DFS) 기반 순열 배정 (1:1 매칭 최적화) — N-Queen 패턴 재응용, 왕복 거의 0회 (체육대회)
- 역방향 재귀 (자식→부모 인덱스 역산, 몫/나머지 활용) — 다단계 칫솔 판매 패턴 재응용 + 신규 수식, 왕복 2회 (유전법칙)
- 이벤트 기반 시뮬레이션 + 우선순위 큐 이중 관리 (대기열/실행대기열 분리) — 신규 도입 완료, 왕복 8회 내외 (운영체제)
- 좌표평면 방향탐색 (dx/dy 순환 배열, 격자 BFS 패턴 재적용 시 부호 재검증 필요) — 재응용 완료, 왕복 4회 (실습용 로봇)
- 그리디 + 최소 힙 반복 병합 (허프만 스타일) — 신규 도입 완료, 왕복 0회 (신입사원 교육)
- 구간 겹침 최대 개수 (투 포인터) — 호텔 대실 패턴 재응용 완료, 왕복 7~8회 (카페 확장)
- 3차원 상태 공간 BFS (좌표 + 아이템 사용 여부 함께 추적) — 신규 도입 완료, 왕복 6회 이상 (보물 지도)
- 트리(이진 트리) + 백트래킹, 정적 구조/동적 상태 분리 관리 — 신규 도입 완료, 왕복 8회 이상 (양과 늑대)
- Trie(트라이) + 접두사/접미사 와일드카드 매칭 (정방향/역방향 이중 트라이) — 신규 도입 완료, 왕복 15회 이상 (가사 검색)

## Lv.4 진입 판단 (Day 136 기준 갱신)
- **긍정적 신호 강화:** 체육대회(백트래킹, N-Queen 재응용)를 코치 개입 최소한으로 첫 코드에서 바로 통과 — 재귀/백트래킹 감각이 "재귀"라는 표찰이 없는 완전탐색형 문제에도 자연 전이됨을 확인. 재귀 관련 재검토 기준(2번: 왕복 3~4회 이내)은 사실상 충족.
- **신규 긍정 신호 (Day134):** 보물 지도(좌표 기반 BFS)에서 배열 크기를 `n+1`로 지적 없이 스스로 설계함 — 그래프형 배열 크기 재검토 기준(1번)에 대한 첫 데이터 포인트 확보.
- **미해결/신규 신호:** "선언은 했지만 반환 흐름에 연결 안 됨" 패턴이 재귀 호출 결과 미반환, 분기 일부 경로 return 누락 등으로 재발하여, 이 패턴군 자체의 완전한 해소는 아직 진행형. "상태 공간을 확장할 때 관련된 모든 참조 지점에 일관되게 반영하지 못하는" 유형의 실수가 Day134~135에 반복 관찰됨.
- **신규 데이터 (Day135):** 트리+백트래킹이라는 완전 신규 패턴에서 왕복 8회 이상 소요됨 — 신규 패턴 도입 세션 특성상 재검토 기준 2번은 아직 미충족이나, 막힐 때마다 원인을 스스로 좁혀나가는 디버깅 태도는 안정적으로 유지됨.
- **신규 데이터 (Day136):** 완전히 새로운 자료구조(Trie)를 개념 설명만 듣고 스스로 설계(정/역방향 이중 구조, Node 필드 구성)해내는 능력이 이번에도 확인됨 — Day135(트리)에 이어 **2세션 연속으로 "새 자료구조를 처음 도입할 때 구조적 설계 자체는 코치 개입 없이 해낸다"**는 패턴이 관찰됨. 또한 이번 세션에서 처음으로 **"시공간 복잡도를 스스로 계산해서 자료구조 선택을 바꾸는" 능력**이 관찰됨(노드당 메모리 40,004바이트 × 최대 노드 수 200만 ≈ 80GB라는 계산을 직접, 정확히 해냄) — 기존 Lv.4 재검토 기준에는 없던 새로운 차원의 긍정 신호. 다만 Map API(`getOrDefault`, `computeIfAbsent`) 문법에서는 인자 개수/순서, 필드-메서드 구분 관련 실수가 같은 세션 안에서 여러 차례 반복됨 — 재검토 기준 3번("같은 세션 안 동일 지적 반복 금지")과는 결이 다르지만(배열 크기/경계조건이 아니라 "새 API 문법" 범주), 계속 관찰이 필요한 지점.
- **결론:** 새로운 자료구조를 스스로 설계하는 능력은 Day135~136 연속으로 뚜렷하게 확인되어 Lv.4 진입 감각의 핵심 축(구조 설계력)은 안정적으로 자리잡은 것으로 판단됨. 반면 "새 API를 정확한 시그니처로 실전에서 바로 사용하는 것"은 아직 반복 학습이 필요한 영역. 사용자 본인은 이 시점에서 Lv.2~3 기본기 재점검을 원함 — 코치 판단으로는 Lv.4 진행에 필수 전제조건은 아니나, API 문법 숙달이 목적이라면 유효한 선택.

### Lv.4 진입 재검토 기준 (변경 없음)
1. 새로운 그래프형 문제를 처음 마주쳤을 때, 배열 크기를 지적 없이 스스로 n+1로 잡는 것이 **2~3세션 연속**으로 확인될 것
2. 한 문제당 코드 제출 왕복이 평균 **3~4회 이내**로 줄어들 것
3. **같은 세션 안에서** 동일한 지적(변수명, 배열 크기, 경계 조건 등)을 두 번 이상 반복해서 받지 않을 것

## 최근 취약 포인트 (누적 추적용)
- **Map API 시그니처(인자 개수/순서) 및 필드-메서드 구분 혼동 (Day136 신규):** `getOrDefault(key, 0)+1`을 하나의 인자로 잘못 묶거나, `computeIfAbsent`의 람다 파라미터를 바깥 스코프 변수와 같은 이름으로 지어 충돌시키거나, `Map` 필드(`children`)를 메서드처럼 괄호로 호출하려 하는 등, 같은 세션 안에서 여러 API 관련 문법 실수가 반복됨. 새 API를 배우자마자 실전에 바로 쓰려다 시그니처를 정확히 확인하지 않고 넘어가는 경향 — 다음에 새 API가 나오면 사용 전에 시그니처(인자 몇 개, 반환값이 뭔지)를 먼저 명확히 짚어주는 절차 강화 필요.
- **경로 위의 "시작 노드(root)" 처리 누락 (Day136 신규):** Trie에서 각 노드마다 카운팅을 누적하는 로직을 `for`문 안에만 넣어서, 확정 글자가 0개인 쿼리(`"??"`)를 검색할 때 정작 `root` 자신은 한 번도 카운팅되지 않는 문제가 발생함. Day135(양과 늑대)의 "루트 이중 카운팅"과는 반대 방향이지만 같은 뿌리의 실수 — "경로의 양 끝(시작점/끝점)이 일반 반복 로직에 자연스럽게 포함되는지"를 항상 별도로 확인해야 한다는 원칙으로 일반화할 수 있음. 단, 원인 자가진단 자체는 유도 질문 이후 정확하고 신속하게 해냄 — 긍정적 신호.
- **"시각(timestamp)"과 "기간(duration)" 혼동 (Day134):** 카페 확장에서 도착 시각(절대적 시점)과 제조 시간(상대적 기간)을 `Math.max`로 섞어 비교하려는 실수가 반복됨. 변수 이름을 `startTime`/`endTime`처럼 명확히 분리한 뒤에야 교정됨.
- **상태 공간 확장 시 참조 지점 전체의 일관성 누락 (Day134):** 보물 지도에서 2차원 visit을 3차원(좌표+신발상태)으로 넓히는 아이디어 자체는 빠르게 캐치했으나, 초기화·범위체크·방문마킹 등 관련된 모든 참조 지점에 빠짐없이 반영하는 데 여러 차례 왕복이 필요했음.
- **구조(자료구조) 확장 시 참조 지점 전체 갱신 누락 (Day135 재발):** 양과 늑대에서 candidate 리스트 관련으로 재발함 — "자식들을 candidate에 추가"는 바로 떠올렸지만, 백트래킹 원복 시 "자식들을 candidate에서 다시 제거"하는 것은 별도 지적 후에야 반영함.
- **초기화 단계의 경계 조건(이중 처리) 실수 (Day135):** 루트 노드를 "이미 방문 완료" 상태로 세팅하면서, 동시에 candidate 목록에도 루트 자신을 넣어버려 재귀 진입 시 루트가 다시 한번 카운트되는 실수 발생.
- **조건식 설계 시 AND/OR 혼동 및 상수 오용 (Day133):** 운영체제에서 `while(!pq.isEmpty() && idx<10)`처럼 논리연산자 방향 착오, 배열 길이 대신 무관한 상수 사용. 반례와 손 시뮬레이션으로 매번 스스로 교정함.
- **배열 인덱싱이 이미 부호를 담고 있음에도 위에 중복 분기(if)를 씌우는 습관 (Day133):** 실습용 로봇에서 `dx[d]`,`dy[d]` 값 자체로 충분한데 `if(d==0||d==2)` 식 분기를 추가로 씀.
- **격자탐색 부호를 다른 도메인(좌표평면)에 무비판적으로 재사용 (Day133):** 예시 손 검증으로 즉시 자가 교정함 — 개선 신호.
- **"선언은 했지만 반환 흐름에 연결 안 됨" 패턴의 새로운 변형 (Day132):** 재귀 호출 자체를 호출만 하고 결과를 받지도 리턴하지도 않는 형태로 재발함(유전법칙).
- **분기가 있는 함수에서 "모든 실행 경로가 값을 리턴하는가" 확인 누락 (Day132):** 유전법칙에서 `if`문만 작성하고 `else`를 빠뜨림.
- **char 리터럴과 String 리터럴 혼동 (Day131):** `'-'`(char)와 `"-"`(String)를 `.equals()`로 비교하며 항상 false가 나와 NPE 발생. Day132에서 개선 확인.
- **배열 인덱스와 저장값의 역할 혼동 (Day131):** N-Queen에서 `g_col[row] = col`과 `g_col[col] = row`를 헷갈림.
- **빈 컬렉션에서 peek()/pop() 호출 순서 실수 (Day129):** `!stack.isEmpty() && 조건` 순서(short-circuit)로 방어해야 함.
- **백트래킹 시 방문 배열(visit) 초기화 위치 오류 (Day129):** 재귀 함수 내부에서 매번 재생성하면 상태가 소실됨. Day132에서 개선 확인.
- **원본 문자열 vs split 결과 배열 인덱싱 혼동 (Day128).**
- **Map 조회 API 선택 혼동 (Day128):** `get`/`getOrDefault`/`computeIfAbsent` 차이 — Day136에서도 문법 세부사항 관련해 계속 관찰 대상.
- **그래프형 배열 크기 설계 실수 (관찰 지속, Day134 긍정 데이터 1건).**
- **대칭 관계 단방향 체크 누락 (Day127 발견):** 관찰 지속.
- **if-else 배타적 분기 처리:** Day128 이후 개선 신호 유지 중.
