## Lv.4 진입 판단 (Day 129 기준 — 보류 유지, 혼재된 신호)
- **긍정적 신호:** 단어 변환(BFS depth 관리 재응용)에서 왕복 1회로 빠르게 수정. 불량 사용자(백트래킹+Set, 신규 설계 패턴)에서도 핵심 아이디어(Set을 이용한 순서무관 중복 제거)는 스스로 정확히 제시했고, 지적받은 부분(visit 배열 스코프)도 1회 만에 이해.
- **부정적 신호:** 주식 가격(모노토닉 스택, 신규 도입)에서 4~5회 왕복 발생 — 다만 이건 Day127처럼 "이미 배운 실수의 재발"이 아니라, "스택에 값 대신 인덱스를 넣어야 하는 이유", "if→while 전환", "push 위치", "빈 스택 예외 방어", "잔여 스택 후처리"까지 **모노토닉 스택이라는 새 패턴을 단계적으로 완전히 체화해나가는 과정**에서 나온 왕복으로, 동일한 지적이 반복된 것은 아님.
- **결론:** 그래프형 배열 크기(n+1) 관련 문제가 이번 세션도 없어서 재검토 기준 1번은 여전히 판단 보류. 기준 2번(왕복 3~4회 이내)은 단어 변환·불량 사용자는 충족, 주식 가격은 미충족(신규 개념 도입 특성 감안 필요). 기준 3번(동일 세션 내 동일 지적 반복 금지)은 이번 세션 전체적으로 충족(각 지적이 서로 다른 원인). **Lv.4 진입은 계속 보류**하되, "신규 알고리즘/자료구조 최초 도입 시 왕복 4~5회는 자연스러운 학습 곡선"으로 보고, 다음 세션에서도 신규 유형 도입 시 왕복 추이를 계속 관찰할 것.

### Lv.4 진입 재검토 기준 (변경 없음)
1. 새로운 그래프형 문제를 처음 마주쳤을 때, 배열 크기를 지적 없이 스스로 n+1로 잡는 것이 **2~3세션 연속**으로 확인될 것

## 최근 취약 포인트 (누적 추적용)
- **빈 컬렉션에서 peek()/pop() 호출 순서 실수 (신규, Day129):** 모노토닉 스택 구현 중, 스택이 완전히 빌 수 있는 상황(연속 하락 등)을 고려하지 않고 `while(prices[stack.peek()] > prices[i])`처럼 조건을 세워 예외 발생. `!stack.isEmpty() && 조건` 순서(short-circuit)로 방어해야 함을 지적 후 즉시 이해·적용. 스택/큐 계열 문제에서 계속 관찰 필요.
- **백트래킹 시 방문 배열(visit) 초기화 위치 오류 (신규, Day129):** 재귀 함수 내부에서 `boolean[] visit = new boolean[...]`을 매번 재생성하면, 배열은 참조로 전달되는데도 이전 단계의 선택 정보가 소실됨. 상위(비재귀) 호출부에서 딱 한 번만 생성해서 재귀 전체가 같은 배열을 공유해야 백트래킹(찜→재귀→원복)이 의미가 있음을 1회 지적 후 정확히 이해.
- **원본 문자열 vs split 결과 배열 인덱싱 혼동 (Day 128):** 문자열을 `split()`해서 새 배열(`str_info`)에 담아둔 뒤에도, 이후 코드에서 원본 변수(`str`)를 계속 인덱싱하려는 실수가 한 문제 안에서 3회 이상 반복됨. 새 변수를 만든 시점에 "이제부터는 이 변수만 써야 한다"를 의식적으로 표시하는 습관 필요.
- **Map 조회 API 선택 혼동 (Day 128):** `get`(없으면 null) / `getOrDefault`(없으면 지정 기본값) / `computeIfAbsent`(없으면 생성 후 저장까지) 세 가지의 차이를 처음엔 구분하지 못해 NullPointerException 유발. "이 Key가 항상 존재를 보장받는가?"를 먼저 판단하고 API를 고르는 습관 필요.
- **낯선 문법/API 최초 사용 시 문법 오류 다발 (재발, 계열 강화):** `computeIfAbsent` 등 새 API를 쓸 때 괄호 불일치, 제네릭 파라미터 위치 오류, 메서드 체이닝 위치 착오 등이 반복됨. Day127의 "PriorityQueue/Comparable 시그니처 혼동"과 같은 계열 — 새 API를 쓰기 전에 정확한 사용 예시를 먼저 한 번 손으로 써보고 시작하는 루틴 필요.
- **그래프형 배열 크기 설계 실수 (관찰 지속, Day 128~129 해당 없음):** 두 세션 연속 그래프 배열 크기 문제가 없어 재발 여부 확인 불가. 다음 그래프 문제에서 계속 관찰.
- **대칭 관계 단방향 체크 누락 (Day 127 발견):** 관찰 지속.
- **if-else 배타적 분기 처리:** Day 128 신규 아이디 추천에서 "동시에 일어날 수 있는 조건은 if/if로 분리해야 한다"를 정확히 구분해서 적용함 — 개선 신호로 기록, 이후 세션에서도 유지 확인 중.
- 코드 신뢰보다 검증 우선, 경계 조건(등호) 민감도, 상태 동기화 누락, for문 증감식/변수명 오타, 다차원 배열 인덱스 범위 혼동, 이분 탐색 종료 조건/경계 이동 방향 착오, 조건 반전 실수, 재귀 함수 return 값 누락 — 기존 항목 유지, Day129에서도 return 누락(불량 사용자 종료 조건)이 1회 관찰되어 계속 추적 필요.
