## 최근 취약 포인트 (누적 추적용)
- if-else 배타적 분기 처리: 독립된 if문을 여러 개 나열하면 한 문자/조건이 중복으로 여러 블록에 걸릴 수 있음 (Day 123, 괄호 회전하기 / Day 124, 두 큐 합 같게 만들기에서 반복 확인 — if/if → if/else if 전환 필요).
- 코드 신뢰보다 검증 우선: 최적화된 코드라도 실제 예제 값으로 직접 트레이싱해서 검증하는 습관 필요 (Day 123, 택배 배달과 수거하기 / Day 124, 호텔 대실 경계값·두 큐 합 반복 횟수 오차 등에서 반복 확인).
- 직관적으로 재현 가능한 코드 선호: 압축된 수식형 최적해보다, 손으로 시뮬레이션 가능한 코드가 실전에서 더 안전하다는 점을 확인함.
- 경계 조건(등호) 민감도: >=와 > 하나 차이로 정답/오답이 갈리는 경우가 반복됨 (Day 124, 호텔 대실 — 청소 종료 시각과 다음 입실 시각이 같을 때 처리).
- 상태 동기화 누락: 값을 한쪽에서 다른 쪽으로 옮기는 로직에서, 받는 쪽만 갱신하고 내주는 쪽 갱신을 빠뜨리는 실수 (Day 124, 두 큐 합 같게 만들기 — sum1/sum2 동시 갱신 누락).
- for문 증감식 오타로 인한 무한루프: 조건식의 변수와 증감식의 변수가 다르게 타이핑되는 실수 (Day 124, 파괴되지 않은 건물 — for(i=1; i<=n; j++)). 코드 작성 후 조건/증감 변수 일치 여부를 눈으로 재확인하는 습관 필요.
- 다차원 배열 인덱스 범위 혼동: N×M이 정사각형이 아닐 때 행/열 반복 범위(n, m)를 서로 바꿔 쓰는 실수 (Day 124, 파괴되지 않은 건물).
