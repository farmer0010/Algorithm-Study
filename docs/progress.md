- Day 172: 부분수열의 합(BOJ 1182, 백트래킹 부분집합) — 통과. 매번 0부터 도는 재귀로 같은 원소 무한 재사용 → 메모리 초과, 고른다/안 고른다 2갈래 + `index == N` 종료 + S = 0 공집합 보정으로 해결. 보정 코드는 탐색 뒤에 두기. 단어 변환(P, 백지 재풀이) — DFS + 방문 되돌리기로 통과. `words[index]`/`words[i]` 혼동, 앞 문제 종료 조건(`length - 1`)을 그대로 가져온 것 교정. 남은 점: target은 있지만 도달 불가일 때 `Integer.MAX_VALUE` 반환, 도착 시 `return` 누락. BFS 버전 미작성.
- Day 171: N과 M (2)(BOJ 15650, 백트래킹 조합) — 통과. 전부 뽑는 재귀에서 시작값 파라미터를 추가하고 `i + 1`을 넘겨 해결. 네트워크(P, DFS, 백지 재풀이) — 통과. 처음에 격자 BFS(dx/dy, 2차원 visited)로 접근해 반례 `[[1,0,1],[0,1,0],[1,0,1]]`에서 5 출력 → "줄 = 연결 목록"으로 전환, 방문 표시 누락으로 무한 재귀 후 교정. 연결 요소의 개수(BOJ 11724, DFS) — 통과. 간선 목록 → 양방향 인접 행렬. 남은 점: dfs 진입 시 `visited[cur]` 표시, `N + 1` 크기와 `-1` 보정 혼용.
- Day 170: 메뉴 리뉴얼(재귀 조합 + Map 집계) — 통과. "후보를 정하고 포함 검사" 방향에서 막혀 "주문마다 뽑아서 센다"로 전환, 뽑기 전 주문 내부 정렬(`toCharArray` → `sort` → `String.valueOf`, `arr.toString()`/`Arrays.toString` 함정), 상자 List → Map 교체, 종료 조건을 `index`가 아닌 `str.length()`로, 재귀 for문(`j + 1`)은 힌트 받음, 개표 2회(최댓값 → `max < 2` 패스 → `entrySet` 수집)는 직접 작성. BOJ 10818·15552 — 통과. 출력 누락, `package` 미삭제, `max = 0` 초기화(음수 범위) 반례로 교정, `println` 반복 → 모아서 출력.
- Day 169: 짝지어 제거하기(스택) — 한 번에 통과. 지운 뒤 만나는 글자 = top, `char == Character`는 언박싱이라 괜찮지만 래퍼끼리 `==`는 참조 비교, `Stack` 대신 `ArrayDeque` 권장. 타겟 넘버(DFS) — 통과. 종료 조건을 `length - 1`로 둔 off-by-one, `return`이 안쪽 if 안에만 있어 범위 초과. `index`의 의미를 "다 정한 개수"로 잡고 return은 무조건 실행.

## 반복되는 약점
- off-by-one, 경계 검사 위치 (좌표를 읽기 전에, 다음 좌표를 계산한 뒤)
- 루프 종료 후 남은 상태 처리, 한 글자 오타(`ticket`/`tickets`, `x = next_y`)
- 람다·컴파일 에러: Comparator의 인자는 원소 자체(`a[1]`), 배열은 값 비교 불가, `Arrays.sort`는 배열용이고 `ArrayList`는 `list.sort`
- 재귀: 결과 모으기(필드 또는 반환값), 되돌릴 대상 전부(`check`와 경로 리스트), 순열·조합 판별
- `&&`/`||` 방향 혼동
- 효율성(O(N²) 이중 for → 정렬/해시) 개선을 먼저 떠올리기
- SQL: 정렬 조건과 컬럼 선택("이름"인지 "ID"인지), 함수 철자
- **(Day153 신규)** 누적값 함수(요금 등)를 이벤트마다 계산하려는 경향 → 누적 후 마지막에 한 번 계산
- **(Day153 신규)** 정수 나눗셈 뒤에 `Math.ceil` 적용(올림 무효) → 나눗셈 전에 `double` 캐스팅
- **(Day153 신규)** `answer`를 선언만 하고 반환 흐름에 연결 안 하거나, 확정 크기 전에 생성하는 패턴 (재발)
- **(Day154 신규)** 시각(`[0]`)과 기간(`[1]`) 혼동 — 시뮬레이션에서 time 점프/누적 시 인덱스 의미를 먼저 확인
- **(Day155 신규)** 맵이 여러 개일 때 키가 "누구의 이름인지" 혼동 → 맵 선언 직후 키/값 의미를 주석으로 적고, 조회 전에 "지금 이 변수는 신고자인지 신고당한 사람인지" 확인
- **(Day155 신규)** `getOrDefault`로 컬렉션에 `add`하는 함정, 람다 파라미터 이름 충돌, `int[]`/`Integer[]` 혼동, 배열 `.length` vs 컬렉션 `size()`
- **(Day156 신규)** 경우의 수 문제에서 나열로 규칙을 찾으려 함 → 종류별 칸(선택지 수) 곱으로 전환. "안 입음" `+1`, 전부 안 고른 경우 `-1`을 빼먹지 않기

- **[Day130 신규 지침]** 문제 선정 직후, check_List 확인만으로 끝내지 말고 반드시 project_knowledge_search로 실제 미풀이 여부를 검증한 뒤 세트를 확정할 것.
