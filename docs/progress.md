## 최근 6일 요약
- Day 168: 요격 시스템(그리디, 끝점 정렬) — 통과. 기준점을 시작/끝점으로 섞어서 반례에서 오답, 열린 구간이라 `s >= idx`면 새로 쏜다. 순위 검색(전처리 + 이분 탐색) — 통과. 이름표 16개 dfs, map value는 List, 쿼리는 `lastIndexOf`로 분리, 정렬 후 하한 탐색으로 효율성 해결.
- Day 167: 정수 삼각형(백지 재풀이, DP max) — 통과. 한 칸의 부모는 윗줄 [i-1], [i] 2개뿐인데 [i+1]을 읽어 터지고, 맨 왼쪽 칸도 [i+1]을 읽어 오답. `k==1` 특수 처리·하드코딩 초기화는 증상 땜질, 윗줄은 `dp`에서 읽고 `answer` 연결. 2 x n 타일링(DP +) — 통과. n=1~5 나열로 점화식, 매 단계 % 처리, `dp`를 두고 재귀 호출하려던 실수를 스스로 교정. 하드코딩 `dp[2]`는 n=1에서 터지므로 개선 여지.
- Day 166: 주식 가격(복습, 스택) — 통과. 확정(pop) 순서대로 `lst`에 쌓고 마지막에 뒤집은 게 오답 원인, 크기가 확정된 배열은 처음부터 만들어 `answer[n]`에 직접 기록. 등굣길(백지 재풀이, DP 2차원) — 통과. 템플릿 5칸으로 한 번에 작성, "왜 최단 경로 개수인가"(방향 고정이라 경로 길이 동일), DP에서 `+` vs `min/max` 구분을 정리함.
- Day 165: 가장 큰 수(백지 재풀이, 커스텀 정렬, 코드 수정 4회) — 통과. 사전순 정렬은 `3`/`30`에서 틀리므로 `(a+b).compareTo(b+a)`로 기준 교체, `[0,0,0]` 처리, `parseInt` 오버플로 주의. 불량 사용자(백지 재풀이 시도, DFS 백트래킹 + `HashSet<HashSet>`) — 세는 단위 오해(응모자 vs 묶음)로 코드 제공받아 따라 침, 백지 재풀이 이월(2~3일 뒤).
- Day 164: 연속된 부분 수열의 합(백지 재풀이, 투 포인터) — 통과. 정답을 찾을 때 `sum = 0`으로 초기화해 구간 상태와 어긋남, 상태 변수는 이동할 때만 더하고 빼기. 입국심사(백지 재풀이, 이분 탐색) — 통과. 시간 T를 정해놓고 검증하는 발상, `max*n`은 `long`으로 곱하기 전에 캐스팅, 합계 조기 `break`, 닫힌 구간은 `left <= right` + `mid ± 1`.
- Day 163: 이중우선순위큐(백지 재풀이, 우선순위 큐 2개) — 통과. 마지막 `for`에서 `pq.size()`가 변하는 값이라 절반만 순회(size를 변수에 저장), `remove(Object)`는 O(N)이라 최악 O(N²)이므로 효율성 버전(`TreeMap`)은 보류. 단속카메라(백지 재풀이, 그리디 구간) — 통과. 끝점 정렬 후 `cam_idx`와 진입점만 비교, 비교 대상은 인접 원소가 아니라 카메라 위치, 걸림/안 걸림 갈래 동작이 뒤바뀐 실수와 정렬 전 초기화 실수를 교정.

## 반복되는 약점
- off-by-one, 경계 검사 위치 (좌표를 읽기 전에, 다음 좌표를 계산한 뒤)
- 루프 종료 후 남은 상태 처리, 한 글자 오타(`ticket`/`tickets`, `x = next_y`)
- 람다·컴파일 에러: Comparator의 인자는 원소 자체(`a[1]`), 배열은 값 비교 불가, `Arrays.sort`는 배열용이고 `ArrayList`는 `list.sort`
- 재귀: 결과 모으기(필드 또는 반환값), 되돌릴 대상 전부(`check`와 경로 리스트), 순열·조합 판별
- `&&`/`||` 방향 혼동
- 효율성(O(N²) 이중 for → 정렬/해시) 개선을 먼저 떠올리기
- SQL: 정렬 조건과 컬럼 선택("이름"인지 "ID"인지), 함수 철자
- **(Day153 신규)** 누적값 함수(요금 등)를 이벤트마다 계산하려는 경향 → 누적 후 마지막에 한 번 계산
- **(Day153 신규)** 정수 나눗셈 뒤에 `Math.ceil` 적용(올림 무효) → 나눗셈 전에 `double` 캐스팅
- **(Day153 신규)** `answer`를 선언만 하고 반환 흐름에 연결 안 하거나, 확정 크기 전에 생성하는 패턴 (재발)
- **(Day154 신규)** 시각(`[0]`)과 기간(`[1]`) 혼동 — 시뮬레이션에서 time 점프/누적 시 인덱스 의미를 먼저 확인
- **(Day155 신규)** 맵이 여러 개일 때 키가 "누구의 이름인지" 혼동 → 맵 선언 직후 키/값 의미를 주석으로 적고, 조회 전에 "지금 이 변수는 신고자인지 신고당한 사람인지" 확인
- **(Day155 신규)** `getOrDefault`로 컬렉션에 `add`하는 함정, 람다 파라미터 이름 충돌, `int[]`/`Integer[]` 혼동, 배열 `.length` vs 컬렉션 `size()`
- **(Day156 신규)** 경우의 수 문제에서 나열로 규칙을 찾으려 함 → 종류별 칸(선택지 수) 곱으로 전환. "안 입음" `+1`, 전부 안 고른 경우 `-1`을 빼먹지 않기
- **(Day156 신규)** 슬라이딩 윈도우 Map 처리 순서: 빼고 → `left++`, 0이 되면 `remove`, 구간 축소는 `while`(`if` 아님)
- **(Day157 신규)** for문 세 칸(선언/조건/증가)의 변수 불일치, 행/열 범위 뒤바뀜
- **(Day157 신규)** 후위 증가 `x++`를 "다음 값 계산"으로 착각
- **(Day157 신규)** 검사 대상을 "지금 칸"으로 착각 (다음 칸을 먼저 계산 후 검사)
- **(Day158 신규)** 여러 곳에서 같은 키가 나올 때 "처음 본 값이 최소"라고 가정 → 기존 값과 비교해서 갱신
- **(Day158 신규)** 일부 케이스만 `-1`인 문제에서 `return`으로 전체 답을 덮어씀 → `answer[i]`에 기록하고 `break`

- **(Day163 신규)** 구간 문제에서 이웃 원소끼리 비교 → "마지막으로 확정한 위치"를 상태 변수 하나로 기억하고 그것과 비교
- **(Day163 신규)** 분기별 동작(카운트 증가 vs 위치 갱신)이 뒤바뀜 → 코드 전에 갈래별 동작을 한글로 표로 정리

- **[Day153 신규 지침]** 당분간 신규 유형보다 **코테 빈출 기본 유형의 백지 재풀이**를 우선한다. 하루 2문제, 복습 큐에서 오래된 것부터 뽑고 예전 코드는 열람하지 않는다. 책 체크리스트의 신규 Lv.1~3은 사실상 소진됐다 (check_List 오표기 많음, 반드시 검색으로 교차검증).
